# UI 验收（分层 + 确定性 + 汇报纪律）

核心命题：**纯读 DOM 只能证明页面长得对，证明不了点了有用。** 声称"做完了"必须附带证据，观感不算证据。

## 一、四层验收表（按层选手段，不越层代查）

| 层 | 查什么 | 手段 |
|---|---|---|
| ① 源码层 | 硬编码颜色、emoji 图标、缺失语义标签、对比度数字 | grep / 静态扫描，不开浏览器 |
| ② 交互层 | **点了有没有用**：菜单展开、删除生效、置顶切换、表单提交 | agent-browser 真浏览器点击 + 断言状态变化（DOM/class/API 结果）；CDP 级操作用 browser-use |
| ③ 渲染层 | 溢出、遮挡、错位、容器撑破 | browser-use 跑 JS 量矩形数字（getBoundingClientRect），对照下方阈值表判定 |
| ④ 视觉层 | 间距节奏、层级感、整体观感 | 截图 + vision-eyes 描述复核；只有这一层允许"观感"发言 |

**重灾区是②**：改完不点一遍等于没验。断言必须落到可观察的状态变化（元素出现/消失、class 切换、请求发出、数据变更），"没报错"不算断言。

## 二、硬阈值表（脚本判定，不靠观感；项目记忆可覆盖默认值）

| 检查项 | 阈值 | 判定方式 |
|---|---|---|
| 交互控件命中区 | ≥ 44×44 px | 量 rect 宽高（含 padding，视觉缩小时可放宽但须显式声明） |
| 容器溢出 | scrollWidth ≤ clientWidth 且 scrollHeight ≤ clientHeight | JS 直读两值比对 |
| 元素对重叠 | 重叠面积 > 较小矩形的 12% → FAIL | 矩形相交检测（layout-guardrails 几何核算已有公式，复用）；**文字元素用 Range 量实际文字矩形**，块级容器盒横跨全宽属正常，盒重叠≠文字重叠 |
| 圆形元素正方性 | w === h（允许 ±1px 取整差） | 量 rect；`border-radius: 50%` 在非正方盒上是椭圆不是圆（双层头像徽章实测：外圈被拉伸 38×35） |
| 双层同心徽章 | 内外圆偏移 | 内外两层 rect 中心差 ≤ 1.5px；量测脚本与三层根因见 frontend-ui-consistency「实测补遗 6」 |
| 文本对比度 | ≥ 4.5:1（大字号 3:1） | 前景/背景亮度计算（WCAG AA） |
| 标题水平偏移 | 同组标题中心偏差 ≤ 1.5px | 量两矩形中心 x 差 |
| 图标体系 | 生产 UI 零 emoji 图标 | 源码层 grep（icon-finder 负责替代方案） |

阈值冲突时项目记忆（AGENTS.md）优先于本表；本表优先于口头"我觉得没问题"。

## 三、横向一致性（众数判定）

同类项核查的**脚本化执行器**（方法论本体在 debug-and-refactor Part B，本节只管怎么判）：

1. 脚本枚举同布局/同角色的全部实例（如同级卡片、同列表行、同层级标题）
2. 每个实例取被检属性值（间距/字号/圆角/色值/结构）
3. **取众数为基准，离群者报 FAIL**
4. 报告格式固定：**「N 处中 N-1 处是 X，这一处是 Y」**——不许笼统说"基本一致"

例外合法：离群者有明确语义理由（主按钮 vs 次按钮）→ 标 PASS 并注明理由，不许静默放过。

## 四、页面覆盖对账

- 验收清单必须与路由表/页面清单**对账**：router（或等价导航配置）里的每个页面，要么被验收，要么显式标注"未验 + 原因"
- 汇报用**页面 × 检查项二维矩阵**，不是流水账："六页签 × 四层"比"检查了流水线页"信息量大一个量级
- **写在清单里 ≠ 查过了**：矩阵里每个格子要能对应到一次真实执行
- **弹窗是独立检查面，单独对账**：页面级扫描扫不到弹窗内部。枚举全部弹窗（含触发路径：点按钮/提交后/边界态触发），每个单独打开跑一遍 × 重叠、间距、双圆同心检查，用"弹窗 × 检查项"矩阵汇报。检测脚本（文字级 Range 重叠判定，兼容黑盒只读约束）见 frontend-ui-consistency「实测补遗 7」。实测教训：页面级扫描全部通过，14 个弹窗逐个打开仍能查出 2 处重叠/挤压

## 三a、按轴验收（X / Y / Z / S）

一致性验收不能只按“字号、颜色、圆角”逐属性看。先把被测界面拆成局部坐标系，再按四根轴分别量。

### X 轴：宽度与左右边界

- 聚类所有同角色元素的左边缘、右边缘、列宽和水平 gap。
- 离群阈值：同一构造线偏离 > 1px 报 FAIL；确实有语义理由的离群单独标注。
- 必须覆盖：内容区左右边界、卡片左右边缘、表头与表体列边界、按钮组水平间距。

### Y 轴：高度、行与基线

- 聚类上边缘、下边缘、行高、文字基线、控件中心线。
- 卡片高度不一致时，先判断是**内容撑开**还是**构造线不同**；内容撑开属 Y 轴内容变化，构造线不同属 Y 轴结构缺陷。
- 折叠/展开只改变 Y 轴占用，不得反过来改变 X 轴分区。

### Z 轴：层级与遮挡

- 枚举所有浮层、sticky、弹窗、下拉、toast，记录层号和 owner。
- 每个重叠必须能回答“谁在谁上面、为什么”；答不出就是碰撞，不是层级。
- 同一层内不允许出现两个争抢焦点的浮层；浮层层号必须来自闭集，不允许 9999。

### S 轴：Z 剖面 × 状态

- 对每个可交互组件，列出 default / hover / focus / selected / disabled / expanded 状态下的层号、占位、可见性。
- 状态切换后，元素不得跳到另一个未声明的层，也不得把下层内容永久压死。
- 弹窗打开时，底层页面必须仍有明确的返回路径；不能靠“看不见”当作不可达。

### 汇报格式

```text
X：N 处边缘，众数 X1，离群 K 处（位置 + 差值）
Y：N 处边缘/基线，众数 Y1，离群 K 处
Z：M 个浮层，层号分布，冲突 K 处
S：P 个组件 × 状态矩阵，缺状态 K 处
```

只报“整体挺齐”不算通过；必须给出每根轴的众数、离群点和差值。

## 四a、按数据增长模型验收（不机械套数量）

列表、卡片、表格、导航不能统一用 `0/1/10/100` 当验收模板。先分类，再选测试数据：

| 数据模型 | 判据 | 必须验的部分 |
|---|---|---|
| **固定结构** | 实例数由产品结构固定，不随业务实体增加 | 缺项、权限隐藏、最长文案、最小可用宽度；不要伪造几百个实例 |
| **单条内容可变长** | 实例数稳定，但名称/描述/数值/翻译长度变化 | 最短、真实最长、连续无空格文本、翻译膨胀、数值极值 |
| **增长型同类集合** | 每新增一个业务实体就新增一项 | 空态、单条、真实常见量、业务峰值、硬上限或超限态；并验证分页/虚拟化/聚合/筛选策略真的生效 |

**判定要求**：

- 被测方必须能说出该集合属于哪一类，以及常见规模、业务峰值、硬上限来自哪里；说不清就按增长型集合处理。
- 「业务峰值」取产品约束、真实数据分布或用户明确给出的上限，不取随意的 100。没有可证明的数字时，明确标为假设并让用户确认。
- 固定结构若被强行加虚拟滚动、搜索、分页，要反过来检查是否过度设计，而不是把复杂度当通过项。
- 增长型集合只验「渲染没崩」不算通过；还要验全局判断是否仍可完成、切换筛选后是否只显示当前范围、聚合值与明细是否对得上。

```text
通过标准 = 规模假设有依据 + 边界状态被真实触发 + 超限策略可观察
失败标准 = 只测了「刚好摆得下」的理想数量 + 没有声明上限 + 峰值时只能靠肉眼猜
```

## 五、验收之后（失败二分）

| 情形 | 信号 | 动作 |
|---|---|---|
| **实现没做到** | 单点阈值不过、点击无响应 | 就地修 → 复测该点 → 对比基线确认没引入新 FAIL。**最多 3 轮**，仍不过 → 停下带着失败数据问用户 |
| **规划错了** | 同类问题出现在改动契约之外；修 A 坏 B（回归） | **立刻停修**。回归是硬错误，优先级高于新功能。给三选项让用户选：①重规划 ②扩范围把同类全改 ③维持现状记录已知问题。不擅自回滚 |

判错代价不对称：把"规划错"当"实现错"继续修，会在错误契约上越走越远——宁可停早。

## 五a、写后数据一致性验收（新建/编辑/删除必跑）

先按 `debug-and-refactor` Part E15 的五类失配做分类：A 局部副本、B 实体创建时机、C 多视图多源、D 读己之写、E 跨端实时。分类错了，后面的断言会全打偏。

凡改动涉及写操作，交互层验收不能只断言“请求 200”，必须走完整闭环：

1. **当前视图**：新建/编辑/删除成功后，不关闭页面，断言当前列表、弹窗、统计卡立即反映新事实；用服务端返回值更新时，断言字段与响应一致。
2. **连续操作**：连续新建两条，第二条创建时第一条仍在选择器/列表中；顺序稳定，不重复、不丢失。
3. **关闭重开**：关闭并重新打开弹窗/页面，断言数据仍在；能扛住一次真实 GET，而不是只活在内存里。
4. **取消语义**：明确验证“取消”是保留已创建实体还是丢弃草稿；实现必须与需求一致，不能靠猜。
5. **多视图一致性**：同一实体出现在列表、详情、统计时，三处读到同一事实源；不允许一处新、一处旧。
6. **失败路径**：模拟写失败，断言用户输入保留、错误可见、本地临时项不被伪装成已保存。
7. **刷新层级**：若必须刷新，记录是局部重取、模块重挂载还是整页硬刷新；业务写入默认不得要求用户 Ctrl+F5。

判定与策略选择见 `debug-and-refactor` Part E15。**保存成功但当前视图没变化，直接判 FAIL，不许用“刷新一下就有了”结案。**
## 五a·一、本地化与文本形变验收

只要界面支持语言切换、账号地区切换、翻译文案或用户自定义长文本，就不能只检查默认语言下“摆得下”。

必须验证：

1. **长度变化**：默认文案、真实最长文案、翻译膨胀后的文案分别渲染；不只测占位符。
2. **换行与截断**：标题、按钮、标签、表头、导航、弹窗标题在目标断点下不溢出、不重叠、不把关键动作挤出视口。
3. **连续文本**：无空格长串、URL、型号、姓名、数字和单位连续出现时有断行或截断策略。
4. **方向与书写模式**：检查 `writing-mode`、`direction`、`text-orientation` 是否被误用；翻译后出现意外竖排、逐字换行或整块旋转，直接判 FAIL。
5. **控件稳定性**：语言切换后按钮高度、图标与文字间距、表单标签对齐、表格列宽、分页器仍可用。
6. **真实切换路径**：通过产品实际的语言切换入口切换后重新验收，不靠手工替换 DOM 文本模拟通过。

判定标准是**内容变化后布局仍可完成任务**，不要求所有语言长得一样。只有默认语言截图通过、没有覆盖长度与换行，不能声称本地化验收完成。

## 五b、桌面端与实时数据专项验收

普通网页验收之外，凡目标包含桌面壳、原生浮窗、本地网关或实时数据，再补这一节：

### 桌面端（Windows GUI）

1. **源码层**：确认发布构建带 `-H=windowsgui`；manifest/图标不能替代 PE 子系统。
2. **产物层**：直接读部署 exe 的 PE `Subsystem`，桌面程序必须为 `2 (WINDOWS_GUI)`。
3. **进程层**：启动后按目标 exe 的**子进程/祖先链**查 `conhost.exe`，不能拿系统全局 conhost 名单误判；桌面壳只应有 WebView2 等预期子进程。
4. **窗口层**：枚举可见 `ConsoleWindowClass` / Windows Terminal 窗口并按 PID 归属；旧进程残留窗口与新进程无控制台要分开报告。
5. **生命周期层**：连续执行“启动 → 停止 → 再启动”，断言端口释放、无残留同名进程、看门狗不会把刚停的实例拉回。

### 实时数据面板

1. **语义分类**：累计量、瞬时速率、区间均值必须分别标注及验证，不能拿均值冒充实时增量。
2. **传输链路**：确认 SSE/推送是否真的在请求落地时发帧；人为断开后能否退化为轮询，并显示正确状态徽标。
3. **区间竞态**：快速连点 `今天 → 7天 → 30天 → 今天`，断言每次图表/标题/表格都属于**当前选中区间**；迟到的旧响应不得覆盖新选择。
4. **局部更新**：只改数值节点，滚动位置、hover、展开态、输入焦点保持不变；结构指纹变化才允许整页重画。
5. **数字动画**：首屏不播、真实变化才播、变化结束后恢复语义单位；角标与单位恢复时长一致，不得无限闪烁。
6. **大数形态**：完整数字与 M/B 缩写在真实渲染宽度下切换，禁止溢出换行和在阈值附近来回抖动。
7. **空态/首帧**：切区间后即使零请求也要立即显示该区间的空图/零值，不允许“等下一笔请求才出现”。

## 六、汇报三件套（声称"完成"的硬门槛）

任何"做好了/改完了/可以了"必须附：

1. **跑了哪些验收**：命令/操作原文（哪层、哪个页面、点了什么）
2. **定量结果**：通过 N / 失败 M，失败项列明（含横向一致性离群者）
3. **覆盖范围**：页面 × 检查项矩阵，未验部分显式标注

三缺一 → 回去补，不许口头补。没有附件的"完成"按未完成处理。

## 与现有体系的接口

- 同类项核查方法论 → debug-and-refactor（本 skill 是其验收场景的执行器）
- 矩形相交/几何核算公式 → layout-guardrails（下沉层，复用不重写）
- 性能指标（LCP/INP/CLS）→ web-perf，与本 skill 并列互补：它管快不快，本 skill 管对不对
- 验收发现的坑要沉淀 → project-memory-sculptor [待确认] 提案
