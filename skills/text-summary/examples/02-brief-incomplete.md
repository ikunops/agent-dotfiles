# 示例 02 · brief 模式 + 输入不完整

用途：验证两件事——`brief` 模式的长度压缩，以及原文截断时的失败分支（步骤：失败分支第 1 条）。

## 输入

```
text: |
  Q3 营收 4.2 亿，同比 +18%，其中海外 1.1 亿。毛利率 41%，比去年同期提升 3 个
  百分点。费用端，销售费用率 22%（去年 19%），主要是东南亚三国的渠道投放。
  经营现金流 3800 万，低于净利润 5200 万，差额来自应收账
mode: brief
```

原文在"应收账"处被截断，最后一句不完整。

## 预期输出

```markdown
## 摘要 · 未命名
- 原文规模：约 120 字 · 模式：brief · 长度占比：5%

### 核心结论
Q3 营收 4.2 亿同比 +18%，毛利改善但销售费用率上升 3 个百分点，现金流低于净利润。

### 关键要点
1. 营收 4.2 亿，同比 +18%，海外贡献 1.1 亿
2. 毛利率 41%，同比 +3 个百分点
3. 销售费用率 22%（去年 19%），投向东南亚三国渠道
4. 经营现金流 3800 万 < 净利润 5200 万

### 待办与风险
- Action：无
- Risk：现金流与净利润差额的解释在原文中断，无法确认成因

> 覆盖度：1/1（输入不完整：末句"应收账"后缺失）｜未覆盖：现金流差额的完整成因
```

## 判定点

- 摘要 4 条要点全部可在原文找到依据 → 步骤 7 通过
- 数字 4.2 亿 / 1.1 亿 / 41% / 22% / 3800 万 / 5200 万 逐字保留，未换算 → 硬约束通过
- 截断处未编造成因，转为 Risk 记录 → 失败分支正确触发
- 无"综上所述""值得注意的是" → 硬约束通过
