# 代码叙事动画纪律

代码动画最常见的失败不是"不够炫"，而是**观众看不懂**：不知道那是什么、看不出发生了什么、文字压在图上一团乱。
下面每条规则都来自真实返工。违反任何一条 = 会被打回重做。

**先读这条元规则**：开工前用一句话回答——"完全不知道背景的人，看这 3 秒能不能认出画面里是什么、发生了什么？" 答不上来就先改分镜，别写代码。

---

## 一、可辨识性优先于氛围

先能认出，再谈好看。

- 画一样东西前，先问"没有上下文的人能认出它吗"。洞穴要有洞口和纵深，乌龟要有甲/头/四条腿的位置关系，人要有头身比例，机器要有可读的部件。
- **暗 ≠ 有气氛**。如果压暗之后只剩一团认不出的黑影，就是失败。暗部必须保留可辨认的轮廓或边缘光。
- 抽象不是借口。允许简化成几何形，但**形状必须指向原型**：俯视的人是一个圆加两点肩，不是随便一个点。
- 交付前做"静音测试"：把画面单独给别人看（不带字幕），对方能不能说出这是什么。

## 二、投影必须统一

一个场景只准一种投影方式，且**所有元素都遵守**。

| 投影 | 特征 | 适合 |
|---|---|---|
| 俯视 | 车顶、头顶、轨道都是线 | 地图、路线、选择题、布局 |
| 侧视 | 剖面、地平线 | 对话、行走、机械 |
| 斜轴 2.5D | 垂直面保持矩形，纵深斜向延伸 | 空间、建筑、投影/影子 |
| 正视 | 平铺、无纵深 | 图表、图标、界面 |

反例：车画侧视、人和轨道画俯视 → 观众会觉得"精神分裂"。
**混用是允许的，但必须是刻意的层级分离**（如：世界俯视，HUD 正视），不能同一层里乱来。

## 三、运动语法：变化必须是"增量"

"生长"指**每一帧是上一帧的超集**。禁止用"滑动现形 / 整块淡入"冒充生长——观众看到的是"一块板盖过来"，不是"东西长出来"。

**判据**：随便抽中间三帧，应能看出**具体长到哪了**，而不是"更完整了"。

常见生长语法（按主体类型选）：

- **描线生长**：线条从起点一帧一帧描到终点，可带发光"笔尖"。适合轨道、路径、数轴、边框、连接线。
- **逐个落下**：重复构件（枕木、砖、楼梯、网格）按顺序一根根出现，出现时自身也从 30% 长到 100%。
- **弹性登场**：单体元素从 0 缩放弹到位（带轻微回弹）。适合人、道具、按钮、图标。
- **结构搭建**：像工地监控那样，从地基开始一层层往上长——先骨架后填充，先结构后装饰。适合建筑、装置、复杂机械。
- **拆改重组**：先长出 A，再拆掉一部分，用拆下的料拼成 B。这是"生长"的高级形态，表达演化/迭代。
- **逐字符输出**：命令行、代码、输入框必须是**一个个字符敲出来**的，带光标闪烁，绝不能整段复制粘贴般瞬间出现。
- **粒子消散 / 聚拢**：沿物体轮廓取样发射粒子，物体淡出、粒子飘散；反向即聚拢成形。适合转场、消失、抽象化。

详细参数与实现要点见 `references/motion-vocabulary.md`。

## 四、文字纪律

- **不写元叙述**。禁止"旁白 / 镜头 / 开始 / 先要有路 / Action"这类导演口令——字幕只写内容本身，不写"我正在做什么"。
- **不加未要求的品牌/系列标签**。用户没要求就不加"XX小故事""XX系列"之类的角标。
- **文字永不压图**。字幕独占底部固定带（不随镜头缩放）；画面内标签（人名、数值）必须避让——要么固定在预留空位，要么随主体移动但始终带偏移。绝不能盖在人脸/身体/关键物体上。
- **文字不叠文字**。两个标签不能压在一起。
- 交付前逐帧扫：有没有字压脸、字压字、字被裁。
- 标签若会与主体重叠，**默认改放固定位置**（如人物上方固定留空），别做"跟随+偏移"的复杂方案，容易在极端位置翻车。

## 五、物体遵守自己的物理

- **车沿轨走**：位置和朝向都从轨道曲线取，不能"横着飞过去"。
- **岔轨/分叉**：两条直线用同心圆弧（或 S 形切线）平滑并入，不能交织成一团。
- **转身要读得出来**：镜像 + 侧向挤压 + 朝向提示（鼻尖/正面感），别只挪个头。
- **机械要有传动**：轮子转、活塞动、连杆连得上，不能各动各的。
- **重力与惯性**：落下的东西加速，抛出的走弧线，别匀速直线飘。

## 六、风格必须真正分家

说"多套风格"时，**禁止用同一套底只改颜色或加滤镜**。每种风格必须是不同的画法。

对每支写清四项，任意两支有三项相同 = 没分家：

- **画法**：单线 / 描边填色 / 色块拼贴 / 网点 / 排线 / 写实
- **投影**：俯视 / 侧视 / 斜轴 / 正视
- **色彩**：几个色、谁主导、什么对比逻辑
- **材质**：纸 / 墨 / 光 / 纯色 / 无质感

滤镜（hue-rotate、sepia 等）只能微调气质，**不能当作风格差异的正当理由**。

## 七、节奏与转场

- 一镜到底时，场景之间靠**形态延续**衔接（上一场景的元素变形/移动成下一场景的元素），不是硬切。
- 转场要有动机：视线引导、物体遮罩、粒子、光变。
- 别生搬硬套运镜。推拉/环绕/视角变化只在故事需要时用，不是每段都加。
- 大动作（撞击、落下、转身完成）卡在重音上，别散在任意帧。

## 八、几何自检：用坐标判重叠，不靠肉眼

重叠不能靠"我看了一眼没问题"来保证——必须用**实测矩形**算。

- 用无头浏览器（Remotion 自带的 Chrome 即可，无需额外下载）加载组件，逐帧 seek，读每个元素的 `getBoundingClientRect()` / `getBBox()`。
- 三类必查重叠：**文字×文字**、**文字×主体图形**、**元素越界**（超出画布）。
- 判定规则：文字×文字用矩形面积（> 较小者 10%）；文字×主体必须用**真实像素命中测试**。
- **包围盒会假阳性**：一艘船的矩形左上角本来是空的，矩形相交不等于图形相交。用 `elementFromPoint` 在文字框内采样点做命中测试，命中率 > 6% 才报警。
- 做命中测试前把整个 svg 设 `pointer-events:none`，只给主体开 `pointer-events:auto`；测完恢复。
- **必须做阴性/阳性对照**：阳性（主体中心必中）+阴性（空白角必不中）。否则检查器返回 0 也可能是坏了而不是干净。
- 取样只能用**当前帧实际可见、且 opacity>0** 的元素（递归乘父级 opacity），否则把隐藏元素也算进来会乱报。
- 主体图形要打标记（如 `data-fig="乌龟"`），否则测不到它与文字的重叠。**标记要精确包住图形本体，不要连标签/引线一起包**，否则会误报。
- 建议抽帧步长 6–10 帧；报告按"类型 + 元素 + 帧区间"合并，只报有效发现。
- 参考实现：`scripts/player-harness.tsx` + `scripts/overlap-check.cjs`。

**位置选择的原则**：字幕不一定要贴底。优先放在**画面里真正空着的那一条带状区域**（如主体与底部元素之间的留白），而不是机械地贴到最下边。多行字幕要预留行高，避免末行被画布边缘裁掉。

## 九、自检：密集抽帧，别只看三帧

**只抽首/中/尾一定漏错**——所有已发现的错都在中间的动作帧。

- 渲染后至少**每 15–20 帧抽一帧**看，重点看：动作中段、转场瞬间、文字出现/消失的帧、极端位置（画面边缘、重叠区）。
- 用一张拼图（sheet）快速扫多帧。
- **看不出问题 ≠ 没问题**。说"我检查过了"之前，先说明抽了多少帧、覆盖了哪些区间。
- 渲染前清缓存（如 Remotion 的 `--bundle-cache=false`），陈旧缓存会静默返回旧画面。

## 十、交付对账

交付前逐项确认（详见 `references/preflight.md`）：

1. 每样东西都能被认出（静音测试）
2. 投影统一
3. 所有变化都是增量，无"滑动现形"
4. 无元叙述文字、无未要求标签、无文字压图/压字（用几何检查器验证，不靠肉眼）
5. 物体遵守物理
6. 风格真正分家（四项对账）
7. 抽帧密度够（每 15–20 帧）
8. 渲染用了正确缓存设置、输出规格符合约定
