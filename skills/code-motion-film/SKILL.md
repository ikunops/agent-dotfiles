# 代码叙事动画纪律

代码动画最常见的失败不是"不够炫"，而是**观众看不懂**：不知道那是什么、看不出发生了什么、文字压在图上一团乱。

**元规则**：开工前用一句话回答——"完全不知道背景的人，看这 3 秒能不能认出画面里是什么、发生了什么？"答不上来就先改分镜，别写代码。

| 文件 | 什么时候看 |
|---|---|

## 〇、开工前先立规格

返工最贵的一种，不是画错了一个形，而是**在错误的规格上把活干完了**。观众说"这不像"，往往不是技法差，是体裁、密度、比例从一开始就不对。

- **先确认体裁**：用户给的往往只是一个名称（栏目名、片种名、风格名）。先查清它的实际形态再设计，不要按字面猜——名称里的每个词都可能骗人。
- **先定后做**：顺序是 文本（说什么）→ 分镜（几拍、什么视角、什么运镜）→ 美术基线（形、色、比例、材质）→ 动作与时间。任一环没定就写代码，后面所有工作都会随规格变动一起作废。
- **参考要量化**：有参考图/参考片时，先量出可比较的数——画幅与遮幅、亮度分布、主色、字阶、留白比例、单镜时长。凭"感觉接近"一定偏离；量化之后才知道差在哪一项。
- **不做最小满足**：完成度按参考的**信息密度**对齐。参考里有的环境层、氛围层、次要角色、材质细节，不能因为"不影响主线"就省掉。少一层，观众就会判"简陋"，哪怕主体完全正确。
- **风格定了就不要偷偷升级**：定为平面就保持平面的**画法**（色块/线条/无写实质感），不要突然改成写实影调与体积光。注意这不是给相机上锁：平面画法照样能环绕、升降、推拉，只要轮廓随相机逐帧重算。
- **规格错了就重启**：连续两轮反馈都指向同一层（"这不是那个东西""画法就不对"），且修补后问题仍在，说明错的不是参数，是规格。回到本节重写一句话规格；只复用与规格无关的部分（工具链、渲染管线、排版函数），造型、构图、镜头语言必须重做。

## 〇·五、片种决定结构

体裁（同一个东西叫什么）与片种（它是哪一类片子）是两件事。片种决定**时间轴由什么驱动**，这比风格更靠前：选错片种，画得再好也是错的。

| 片种 | 时间轴驱动 | 镜头单位 | 文字角色 |
|---|---|---|---|
| 讲解片 / 科普 | 讲解逻辑：概念 → 机制 → 例证 | 一镜到底或少量镜头 | 字幕承担主要信息 |
| 知识栏目短片 | 观点推进 + 情绪节奏 | 按论点切分镜 | 文字是主体，画面是氛围 |
| 故事片 / 叙事短片 | 事件因果 + 情绪曲线 | 分镜，运镜服务情绪 | 文字极少，靠画面叙事 |
| 教程 / 上手视频 | 操作顺序 | 固定机位或步骤特写 | 步骤 + 逐字符输出 |
| 产品 / 宣传片 | 卖点排序 + 节奏高点 | 分镜 + 运镜，节奏快 | 短句卖点 |
| 音乐驱动 / MV | 音乐节拍与小节 | 卡点切换 | 随乐句出现的关键词 |

- **先判片种再动手**：一句话回答"这支片的时间轴由什么驱动"。答不上来，说明还没想清。
- **同类不等于同法**：同样是讲解片，讲机制和讲历史的时间结构不同；同样是故事片，靠对白和靠动作的结构也不同。片种只是第一层，第二层是这支片的驱动方式。
- **混用要有主片种**：允许在一支片里混入别的讲述方式，但主时间轴不能被换掉；切换点要让观众感到"换了一种讲法"。
- **片种决定文字密度**：故事片里塞满字幕、讲解片里几乎没字，都是片种错位。文字多寡由片种决定，不由风格决定。

**四个轴是独立的，不要混为一谈**：

| 轴 | 回答的问题 | 例子 |
|---|---|---|
| 片种 | 这是什么片子 | 讲解片 / 故事片 / 教程 / MV |
| 风格 | 用什么画法画 | 线条 / 像素 / 扁平矢量 / 贴纸 / 青铜质感 |
| 生长方式 | 东西怎么出现 | 描线 / 逐个落下 / 结构搭建 / 拆改重组 / 逐字符 |
| 转场 | 场景之间怎么接 | 形态延续 / 推拉 / 环绕 / 镜像 / 粒子 / 一镜到底 |

常见错误是**把风格轴做成了生长语法轴**：说好四套风格，结果四支都是线条动画，只是线条粗细不同。风格要变的是画法与材质，不是"怎么长出来"。

详细要求与每类的典型失败见 `references/genre-playbook.md`。

## 一、先能认出，再谈好看

- 画一样东西前，先问"没有上下文的人能认出它吗"。原型的识别特征必须齐全：关键部件在、比例对、部件之间的连接关系成立。
- **暗 ≠ 有气氛**。压暗之后只剩一团认不出的黑影就是失败。暗部必须保留可辨认的轮廓或边缘光。
- 抽象不是借口。允许简化成几何形，但**形状必须指向原型**；简化后仍要保留可辨认的特征。
- 交付前做"静音测试"：把画面单独给别人看（不带字幕），对方能不能说出这是什么。
- **画面单薄时，先补层级再谈特效**。观众感到的"简陋"通常来自层级缺失：没有环境层、没有次要元素、没有前后景分离、没有材质区分。先补齐 背景环境 → 中景主体 → 前景遮挡 → 信息层，再考虑光效。缺的若是**结构信息**（这是哪、离多远、什么材质），补结构，不是加光。
- 压暗不等于有质感。整体压暗会变成一团黑；要有明确的明暗分区。清晰度也是质感的一部分，放大后边缘发虚、噪点成块等于白做。

## 二、投影必须统一：同一帧用同一台相机

**这一节管的是同一帧内的自洽，不是给相机上锁。**

一个场景里所有元素必须由**同一组相机参数**算出来。反例不是"用了俯视又用了侧视"，而是**同一帧里两个东西的投影对不上，又不分层**：一个按侧视画，一个按俯视画，却在同一平面里互相遮挡 → 观众觉得"精神分裂"。

| 投影 | 长什么样 | 适合 |
|---|---|---|
| 俯视 | 车顶、头顶、路线都是线 | 地图、路线、选择题、布局 |
| 侧视 | 剖面、地平线 | 对话、行走、机械 |
| 斜轴 2.5D | 垂直面保持矩形，纵深斜向延伸 | 空间、建筑、投影/影子 |
| 正视 | 平铺、无纵深 | 图表、图标、界面 |
| 自由视角 | 每帧按相机位置重算投影 | 运镜、环绕、升降、推拉 |

混用是允许的，但必须是刻意的层级分离（如：世界俯视，HUD 正视）。判断标准不是"用了两种投影"，而是"这两层是不是本来就该在两套空间里"。

### 2.1 平面画法不等于相机不动

**"平面风格"指的是画法**——色块、线条、无写实材质、无体积光；**不是说相机被焊死在一个角度上。**

逐帧渲染时，每一帧本来就是**重新画的一张图**。相机参数动一点，这一帧里所有形状就重算一遍。所以平面风格当然可以环绕、可以升降、可以推拉——观众看到的"3D 感"从来不需要真的 3D，它来自**连续多帧的透视变化**。

只有一种做法是假的：**把已经画好的一整层做 `transform`**。那是把一张纸片整体旋转/整体平移，形不变、只变位置。

| 运镜 | 逐帧重算的样子（对） | 偷懒的样子（错） |
|---|---|---|
| 环绕 | 正圆逐步变椭圆、柱面露出弧面、遮挡关系随角度变、背面元素转出来 | 整张图 `rotateY` / `rotate3d`，像纸片翻转 |
| 升降 | 地平线位置变、上下间距变、遮挡范围变、俯视程度变 | 整层 `translateY` |
| 推 | 近处放大快、远处放大慢、深度间距拉开、边缘移出画外 | 整层等比 `scale` |
| 拉 | 反之，近处先退、远景后并 | 整层等比 `scale` |
| 变焦 | 只改视野和主体大小，透视关系**不变** | 跟推镜头混为一谈 |
| 摇 / 平移 | 视差：近处位移大、远处位移小 | 所有层同速平移 |

**判据一句话**：这一帧的形，是不是由这一帧的相机算出来的？

平面不必画光影体积，但**必须画轮廓变化**。轮廓不变，观众就看不出相机在动——这时候你说"这是环绕"，观众只会觉得"这纸在转"。

### 2.2 逐帧重算的最低要求

不用真的搭 3D 引擎。只要每帧参数化重算，二维投影完全够用：

- **把结构写成参数，不写成静态坐标**：物体有位置、朝向、尺寸；相机有方位角、俯仰、距离、焦距。每帧先算相机，再由相机投影出这一帧的多边形。
- **遮挡由深度排序决定**：按相机方向算每个面/每个物体的深度，远的先画。环绕时谁挡谁自然就变了，不能靠手工调图层顺序。
- **可见面按角度取舍**：柱体的正面/侧面、盒子的顶面/侧面，角度过了阈值就不画。这是"转过去"的核心，比渐变遮罩可信得多。
- **轮廓点每帧重算**：只要外轮廓在动，平面色块也能读出体积；轮廓不动，加多少阴影都像贴纸。
- **允许简化成低面数**：8–16 段的多边形柱体、几个盒子拼建筑，就足够读出环绕；不需要曲面细分和光照。
- **镜头参数走同一条时间线**：相机和元素共用同一个 `frame`，不要一个用 CSS transition、一个用逐帧计算，否则两者永远对不齐。

**常见的假运镜**：给整层加 `perspective` + `rotateY`；用 `scale` 冒充推拉；用 `translate` 冒充升降；用背景图视差冒充环绕。抽三帧看物体的**形状**有没有变，就能识破。

可运行参照实现：`scripts/camera-projection.cjs --selftest`。它把"环绕时轮廓必须变、平移时轮廓必须不变"直接写成了断言。

## 三、运动语法：变化必须是"增量"

"生长"指**每一帧是上一帧的超集**。禁止用"滑动现形 / 整块淡入"冒充生长——观众看到的是"一块板盖过来"，不是"东西长出来"。

**判据**：随便抽中间三帧，应能看出**具体长到哪了**，而不是"更完整了"。

常见生长语法（按主体类型选）：

- **描线生长**：线条从起点一帧一帧描到终点。适合骨架、路径、边框、连接关系。
- **逐个落下**：重复构件按顺序一个个落位，落位时自身从 30% 长到 100%。适合砖、台阶、栏杆、座席这类重复件。
- **弹性登场**：单体从 0 缩放到位，带轻微回弹，锚点在生长基座。适合人、道具、按钮、标注点。
- **结构搭建**：像数月延时摄影，地基→骨架→楼板→墙体→装饰逐层长；脚手架可拆，拆本身也是动画。
- **拆改重组**：先长成 A，再拆掉一部分，用拆下的料拼成 B；拆除是逆生长，不是淡出。
- **贴片生长（年画式）**：画面分块，按顺序一块块贴上去，贴到哪哪显形；每块独立进度，贴边可见。
- **水墨侵染**：墨点沿纸纤维扩散，边缘有机、速度衰减；用噪声阈值推进，不是放大圆形遮罩。
- **逐字符输出**：命令行、代码、输入框必须一个个字符敲出来，带光标，执行结果逐行刷出。
- **粒子聚拢**：粒子从外聚成形，适合从抽象到具体。

**两个轴要分清**：以上是**生成方式**（元素怎么出现），与**转场方式**（场景怎么接）是两回事。唯一合法的跨界是粒子——聚拢是生成，消散是转场。完整分类与选择表见 `references/generation-grammar.md`。

### 3.1 并发是允许的，但每条生长必须有接口

多条生长同时推进本身没有问题，出问题的是**它们彼此没有约定关系**：各走各的时钟、各自的端点、各自的曲线，最后在画面上互相穿过——看起来就像乱藤。

**根因**：生长被当成"播放一段动画"，而不是"往一个已有的结构上接东西"。没有接口定义，就没有协调的依据。

对任意一条生长，必须能回答三个问题：

1. **起点依附于什么**——从已存在的几何上长出来，还是凭空出现在半空？
2. **终点接到哪里**——接另一条生长的端点、接一个具名节点，还是自己收尾？
3. **与其它生长的相位关系**——同时、等待对方到位，还是接力？

做法：

- **同时生长**：允许并行，但共享同一把尺子（同一弧长速度、同一构件节拍），相位差写成显式常量。不要每段各起一个 `start`，让它们碰巧对齐。
- **接力生长**：交接点抽成一个共享坐标常量，前段用它裁剪、后段用它起笔。两段引用同一个数，而不是各自写一个"差不多"的值。
- **未连接处留白**：两条尚未接上的生长之间应有一段可读的空隙，而不是随意交叉。若确实需要相交，必须在交汇处给出明确的层级或遮挡关系。
- **前沿可辨**：每条生长推进时，其前沿应当能被看见（线头、正在出现的构件边缘）。多个前沿同时存在可以，但每个都要能定位。

**自检（可测）**：逐帧记录每条生长的前沿坐标，检查是否存在**未被声明为交接/交汇的轨迹相交**；交接帧上前段末点与后段首点的坐标差必须为 0。

### 3.2 所有可见事件从同一个世界状态派生

**根因**：文字、构件、人物、镜头各自读不同的时间变量。画面一改节奏，只有其中一部分跟着动，于是错位。

- 建立一个单一状态量（进度、已铺设长度、已用时间），所有派生量从它算出来。
- 文字的出场条件是**谓词**（"某物已到位""某段已闭合"），不是帧号。这样改节奏时文字自动跟随。
- **判据**：调整一个节奏常量后，如果需要在三处以上同步改数，说明时间源已经分裂；合并回一个再改。

### 3.3 空间冲突在设计层解决，参数层修不好

**根因**：几何先被定死，动作再往里塞。当某一拍要求两个元素同时占据同一块像素，任何局部微调（挪几像素、调透明度、加描边）都无法让观众读出两件事——因为冲突不在数值里，在构图里。

**判据**：如果这一拍"观众必须看见的东西"被另一个元素遮挡到读不出，且已经试过位移、缩放、层级三种手段仍不可读，就判定为设计冲突。

**做法**：回到这一拍的目的——观众此刻必须读到什么？然后重排走位、时序、层级或视角。**换构图，不是换数字。**

**止损**：同一处连续改 3 次仍读不通，停止调参，重新设计这一拍。继续试第 4 个数值只是在消耗时间。

## 四、文字纪律

- **不写元叙述**。禁止"旁白 / 镜头 / 开始 / Action"这类导演口令——字幕只写内容本身，不写"我正在做什么"。
- **不加未要求的品牌/系列标签**。用户没要求就不加"XX小故事""XX系列"之类的角标。
- **文字永不压图**。字幕放在预留的留白带（固定不随镜头缩放，位置按实际空区选，不必贴底）；画面内标签（人名、数值）必须避让——要么固定在预留空位，要么随主体移动但始终带偏移。绝不能盖在人脸/身体/关键物体上。
- **文字不叠文字**。
- **标签默认改放固定位置**（在主体扫掠范围之外的留白处），别做"跟随+偏移"的复杂方案，容易在极端位置翻车。
- **文字颜色由它脚下的背景决定**，不由全片调色板决定。浅底用深字，深底用浅字；跨明暗交界时要挪位置，别让一行字一半深一半浅。
- **不写互动引导**。"评论区告诉我""你选哪个"这类是平台话术，不是内容。需要互动就用内容本身发问，让观众自己想。
- **每屏只承载一个意思**。长句拆成多屏，别靠缩小字号硬塞。
- 交付前逐帧扫：有没有字压脸、字压字、字被裁、字出框。

## 五、物体遵守自己的物理

- **沿路径运动**：位置和朝向都从同一条路径曲线取，不能脱离路径横移或飞越。
- **分叉与汇入**：两条路径用同心圆弧（或 S 形切线）平滑并入，不能交织成一团；分叉角度要符合该物体真实的转向能力。
- **朝向变化要读得出来**：用镜像、侧向挤压、正/背面特征变化等手段表达转向，不要只平移一个局部部件。
- **机械要有传动**：轮子转、活塞动、连杆连得上，不能各动各的。
- **重力与惯性**：落下的东西加速，抛出的走弧线，别匀速直线飘。
- **道具要符合场所**：先问"这个地方会不会出现这个东西"。不合场所比画得丑更致命。
- **接触关系要对**：坐就是坐（臀在座面、腿自然下垂），站就是站，拿就是手在物体上。靠"大概挨着"蒙混，放大看会露馅。
- **对称物体要给朝向线索**：圆、正多边形、球这类转起来看不出的形状，转向时必须另加方向提示（高光偏移、正面标记、附属物摆动），否则观众只看到"抖了一下"。
- **路径要符合环境**：绕路要沿真实道路走，并让观众看见"原来的路"（旧路线可留虚线）；不能凭空画一条弧线穿过建筑。
- **构件沿弧长等距**：弯道上的重复构件按累积弧长重采样，不要按索引等步长——直线没问题，弯道会挤成一团。

## 六、风格必须真正分家

说"多套风格"时，**禁止用同一套底只改颜色或加滤镜**。每种风格必须是不同的画法。

对每支写清四项，任意两支有三项相同 = 没分家：

- **画法**：单线 / 描边填色 / 色块拼贴 / 网点 / 排线 / 写实
- **投影**：俯视 / 侧视 / 斜轴 / 正视 / 自由视角（每帧重算）
- **色彩**：几个色、谁主导、什么对比逻辑
- **材质**：纸 / 墨 / 光 / 纯色 / 无质感

滤镜（hue-rotate、sepia、invert 等）只能微调气质，**不能当作风格差异的正当理由**。

**滤镜会翻转明暗极性**：加 `invert` 之后，你以为在画"浅底深线"，实际得到"深底浅线"。所有颜色判断必须以**渲染后的真实像素**为准，不能凭源码里的常量。一旦用了 `invert`，在文件头写一行注释记下极性。

## 七、节奏与转场

### 7.1 时长：只压"等待"，不压"阅读"

- 给每屏文字算一个**可读时长下限**（按字数计），低于下限的镜头不允许存在。可用 `scripts/readability.cjs` 检查：传入字幕时间表，它会报停留不足、切换过急、时间重叠。
- 提速优先砍：空镜停留、入场缓动的尾部、转场过程、重复动作。**不要砍文字停留与关键动作的完成瞬间。**
- 节奏要**有起伏**：信息密的段落放慢，过渡段落加速。全片等速会像幻灯片，等速加速会像快进。
- 判断标准不是"总时长变短了"，而是"每一屏都读得完，且没有一屏在空等"。

### 7.2 转场：先保连续性，再选手法

观众觉得转场像 PPT，通常不是切得太多，而是**画面断了**：黑屏、闪白、整块淡入、静帧等待后再出现新场景。真实视频的转场至少保留一项跨场景的连续证据：**同一主体、同一形状、同一运动、同一空间、同一方向**。能一镜完成就不切；必须换场时优先做同形接力或单体环绕/穿入；线条、粒子必须把旧画面的残余物当成新场景的结构起点。黑场/闪白只用于明确的时间跳跃或章节分隔，不能当默认换场。

完整判定顺序、三类转场模板、反例和抽帧验法见 `references/transition-continuity.md`。

### 7.3 转场四组，不要混着用

| 组 | 手法 | 什么时候用 |
|---|---|---|
| 运镜 | 推、拉、平移/摇、升降、环绕、变焦、甩镜 | 空间连续、要强调"没有中断" |
| 形变 | 形态延续、镜像、遮罩、同构替换 | 两个场景有共同的形或结构 |
| 材质 | 粒子、水墨、光变、烟/雾/水/沙、撕裂/翻页 | 情绪转折、时间流逝、风格化段落 |
| 剪辑 | 硬切、叠化、跳切、闪白/闪黑 | 时间跳跃、压缩过程、强节奏 |

- **必须有动机**：转场要回答"为什么现在换"。
- **方向要有语义**：同一方向全片表达同一种关系（向左=前进、向右=回溯），不要混用。
- **时长要短**：转场是标点不是句子，多数 0.3–0.8 秒；叠化可到 1.5 秒。
- **文字层独立**：转场作用于画面层，字幕固定在屏幕层，不跟着翻转、缩放、消散。
- **投影一致**：镜头可以环绕、升降、推拉；要求是同一帧所有元素由同一组相机参数算出，且元素形状随相机重算，不是整层做 `transform`。
- **卡拍**：有音乐时，转场完成点落在重音或小节线上。
- **一镜到底不是一种转场**，是一整套约束：空间连续、主体连续、路径预先规划、在明确的一帧完成交接、元素复用、持续微动。

完整分类与选择表见 `references/generation-grammar.md`。

## 八、几何自检：用坐标判重叠，不靠肉眼

重叠不能靠"我看了一眼没问题"来保证——必须用**实测矩形**算。

- 用无头浏览器（Remotion 自带的 Chrome 即可，无需额外下载）加载组件，逐帧 seek，读每个元素的 `getBoundingClientRect()` / `getBBox()`。
- 三类必查重叠：**文字×文字**、**文字×主体图形**、**元素越界**（超出画布）。
- 判定规则：文字×文字用矩形面积（> 较小者 10%）；文字×主体必须用**真实像素命中测试**。
- **包围盒会假阳性**：形状不规则的物体，包围盒的角上往往是空的。用 `elementFromPoint` 在文字框内采样点做命中测试，命中率 > 6% 才报警。
- 做命中测试前把整个 svg 设 `pointer-events:none`，只给主体开 `pointer-events:auto`；测完恢复。
- **必须做阴性/阳性对照**：阳性（主体中心必中）+阴性（空白角必不中）。否则检查器返回 0 也可能是坏了而不是干净。
- 取样只能用**当前帧实际可见、且 opacity>0** 的元素（递归乘父级 opacity），否则把隐藏元素也算进来会乱报。
- 主体图形要打标记（如 `data-fig="figure-1"`），**标记要精确包住图形本体，不要连标签/引线一起包**，否则会误报。
- 建议抽帧步长 6–10 帧；报告按"类型 + 元素 + 帧区间"合并，只报有效发现。
- 参考实现：`scripts/player-harness.tsx` + `scripts/overlap-check.cjs`。
- 除文字外，**同类元素之间也要查**：并排的伞、成排的人、密集的构件，必须两两比矩形。重叠不一定是错，但必须是设计过的（遮挡关系明确），不能是随机撒点撒出来的。
- **分层是硬要求**：每个元素声明自己属于哪一层、与谁同层。同层元素默认不得重叠；跨层重叠必须是有意的遮挡，且层级顺序固定。
- 相邻但不该接触的元素，留出可测的最小间隙（例如不小于自身尺寸的 2%），并把间隙写成常量，别靠手调。

### 8.1 静态没撞 ≠ 永远不撞：必须扫"轨迹 × 时间线"

只检查某一帧的矩形是否相交是不够的。**这一帧没撞，不代表后面某帧不会撞。**

移动的元素（车、滑块、光标、扫描线、镜头）会在时间线上"扫过"大片区域，静止的文字/标签可能正好落在它的扫掠路径里。

- 检查器必须**逐帧（或小步长如 4）seek 整条时间线**，而不是抽查几帧。
- 对每个会动的元素，记录它在**每一帧**的矩形与不透明度，形成轨迹；再与所有文字标签做逐帧比较。
- 报告必须包含**帧区间**（如 `f828-934`），让人知道"什么时候撞、撞多久"，而不是只给一个布尔值。
- 运动元素的"扫掠包络"（所有帧矩形的并集）可以用来**提前设计**：标签必须放在包络之外，或设计明确的离场时机（引线跟随、淡出、上移）。
- 注意"包络不等于当前帧"：后期缩放、局部放大或镜头推近都会让实际覆盖范围超出逐帧包围盒的并集。安全距离要按最终镜头下最大的可见尺寸算。

### 8.2 允许的情况（不算碰撞）

- **自己的底板**：完全包住文字、且面积 ≥ 文字 2.2 倍的色块/面板，是文字自己的背景，不算碰撞。
- **瞬态掠过**（可选宽限）：若某帧重叠面积很小且只持续 1–2 帧、视觉不可读，可记入报告但标为"低危"，由人决定是否修。默认仍建议修。

### 8.3 报告要区分置信度

- **像素命中**（用 `elementFromPoint` 采样）：高置信，一定是真撞。
- **矩形相交**（纯包围盒）：可能假阳性。两类分开列，先修像素命中。
- **采样网格有盲区**：7×4 采样会漏掉"细线擦过文字一角"（如 3px 横线只擦 6px 宽）。所以矩形相交这一路不能省，两条结果都要看。

**位置选择的原则**：字幕不一定要贴底。优先放在**画面里真正空着的那一条带状区域**，而不是机械地贴到最下边。多行字幕要预留行高，避免末行被画布边缘裁掉。

### 8.4 状态判断必须用「单调量」，不能用瞬时位置

几何检查器只能发现"两个东西撞了"，**发现不了"东西该出现却没出现"**。

典型 bug：用物体的当前坐标判断"某事件是否已经发生"。当物体从相反方向进入时，初始坐标就已经落进"已发生"的区间，事件从第一帧起被误判；若坐标本身还会往返，判断结果会来回翻转，已经消失的东西又冒出来。

- 表示"已经发生过/已经越过"的量，必须是**单调不回退**的（进度 0→1、累计位移、已过去的时间）。
- 从"来回摆动的坐标"或"瞬时位置"推导状态时，先算一个单调进度量，再拿它做判断。
- 交叉影响的动作要**显式门控**：一个物体离开某条路径后，不应再影响该路径上的其它对象 → 用单调进度上的窗口显式关掉，例如 `1 - clamp((t - a) / (b - a))`。
- 自检时不能只查"有没有碰撞"，还要逐帧问**"这一帧该出现的东西，出现了没有"**：把每个元素的 opacity/尺寸沿时间线打印出来。静帧目视 + 逐帧数值，两者都要。

## 九、交付前的两轮自检

### 9.1 密集抽帧

**只抽首/中/尾一定漏错**——已发现的错几乎都在中间的动作帧。

- 渲染后至少**每 15–20 帧抽一帧**看，重点看：动作中段、转场瞬间、文字出现/消失的帧、极端位置（画面边缘、重叠区）。
- **平面画法 + 运镜时，抽帧看的不是位置，是形状**：同一个物体在三个时点的轮廓是否真的在变。形不变 = 整层 transform 在冒充。
- 用一张拼图（sheet）快速扫多帧。
- **看不出问题 ≠ 没问题**。说"我检查过了"之前，先说明抽了多少帧、覆盖了哪些区间。
- 渲染前清缓存（如 Remotion 的 `--bundle-cache=false`），陈旧缓存会静默返回旧画面。
- 验收帧必须来自**最终交付文件**（最终 MP4 / 最终单文件 HTML），不是中间渲染图、草稿视频或开发预览。

### 9.2 源码、产物与交付物对账

**源码改过不等于交付物改过。** 凡是“源码 → 构建 → 打包/内联/渲染 → 最终文件”的链路，必须逐层确认最后一层真的换了：

- 单文件 HTML / 离线交付：源码改完后必须重新 bundle 并重新内联；双击版与 `index.html` 可能引用两个不同的产物。
- Remotion / 视频：渲染命令启动前确认入口、`public/` 资源与输出路径；陈旧 bundle cache 会静默返回旧帧。
- 同一交付有别名/副本时，用哈希或字节大小确认它们一致，不靠文件名“看起来像”。
- 验收对象必须是**最终可交付文件**：视频从最终 MP4 抽帧，网页从最终单文件或部署 URL 打开；中间渲染图、草稿视频和源码预览都不算交付证据。
- 改完源码后把“构建命令 + 产物路径 + 验证方式”写进 README；下次先照命令重建，不凭记忆手工内联。

### 9.3 版本与素材

- **已确认的产物是规格，不是灵感**。确认版要反推成具名常量（坐标、间距、比例）并注明来源；后续只做增量，改动已确认的结构必须显式提出并说明理由，并做同机位截图 diff。
- **被否决的素材要隔离**。否决版本整目录归档（如 `_rejected/v3`），主流程引用路径不再指向它；出片前做一次资源清单核对，用哈希或文件名前缀区分版本，不靠"我记得改过了"。

## 十、交付对账

逐项确认（详见 `references/preflight.md`）：

1. 每样东西都能被认出（静音测试）
2. 投影自洽：同一帧同一台相机；运镜是逐帧重算，不是整层 transform
3. 所有变化都是增量，无"滑动现形"
4. 无元叙述文字、无未要求标签、无文字压图/压字/压边
5. 物体遵守物理（路径、接触、朝向、传动、场所）
6. 风格真正分家（四项对账）
7. 并发生长各有明确接口（起点/终点/相位）；交接点坐标一致；未被声明的轨迹不相交
8. 所有可见事件从单一世界状态派生
9. 抽帧密度够（每 15–20 帧），并说明覆盖区间
10. 渲染用了正确缓存设置、输出规格符合约定
11. 规格先立住了，且未被后续优化悄悄换掉
12. 每屏文字都超过可读时长下限；提速砍的是等待，不是阅读
13. 画面层级完整，质感不是靠压暗和加光堆出来的
14. 同类元素两两查过重叠；同层不重叠，跨层遮挡有明确顺序
15. 没有出现已否决版本的素材
16. 片种判定清楚，且全片时间轴确实由它该有的东西驱动
17. 每个转场至少保留一项连续证据（主体/形状/运动/空间/方向）；同形接力要对齐中心、大小、转向、速度；单体环绕不能靠整层 transform
18. 黑屏/闪白/整屏淡入没有当默认换场；章节黑场逐条登记 allowBlack/allowWhite 与 reason

## 十一、复刻参考时

复刻不是照着看到的样子画，而是**先把参考变成可核对的数，再决定用哪种技术实现**。详见 `references/reference-replication.md`。

- 先判这是什么画法，再选工具。平面就平面，别用 3D 去逼近平面；写实就打光，别用矢量硬描。
- 量出可比对的量级：画幅/遮幅、主体占屏比、亮度分布、主色、边缘锐度、单镜时长。
- 放大看边缘。参考锐利就保持锐利；发虚、噪点、脏污感都是失败信号。
- 复用参考的**结构逻辑**（路线怎么走、视角怎么变、信息什么时候出现），而不是复刻某一张截图的像素。

## 附录：这套纪律本身怎么演进

一条规则如果换个题材就失效，那它不是规则，是这次事故的复盘笔记。

**迁移检验**：把规则里的名词全部抽掉，只留结构——"谁、在什么条件下、因为什么、必须怎样"。抽掉名词后句子仍成立，才可以进这份 skill；否则它属于项目备忘。

**判断标准**：这条规则是在描述**问题的成因**，还是在复述**上一次的具体修正**？前者可迁移，后者只能防住同一部片。
