# 图片主导的代码合成

本文件处理一种混合形态：画面主体来自 AI 静帧、照片、扫描图、手绘图或其它栅格 plate；Three.js / Remotion / SVG / Canvas / CSS / GSAP / HyperFrames 负责时间线、镜头运动、叠加层、文字、转场和最终渲染。

它不教图片模型怎么生成，也不把静帧缩放说成真实运镜。图片资产生成属于上游；本 skill 只约束“拿到资产之后，如何可靠地编排成视频”。

## 一、什么时候读这份文件

适用：

- 一支 MV、故事片、讲解片或产品片，主要画面是一批已经生成好的图片。
- 用代码把多张静帧组织成时间线，并加入字幕、叠层、Ken Burns、章节卡和转场。
- 图片由 SDXL、Midjourney、ComfyUI、摄影、扫描或手绘提供，代码负责合成。
- 需要把“图片生产”和“视频编排”分开验收，避免把生成失败和合成失败混在一起。

不适用：

- 纯程序化图形、纯 Three.js 场景、纯 SVG / Canvas 动画，没有栅格 plate。
- 需要真正 3D 环绕、穿入或逐帧相机投影，却只有一张平面图；这种情况要按主 skill 的相机投影规则处理，不能拿 Ken Burns 冒充。

## 二、先写 manifest，再写合成

图片一多，最大的风险不是某一张不好看，而是**镜头、素材、时间、字幕和输出路径各自维护**。先建立一份单一数据源，后续脚本、子合成和验收都从它读取。

最小契约：

```json
{
  "meta": {
    "title": "项目名",
    "fps": 30,
    "width": 1920,
    "height": 1080,
    "duration": 120.0
  },
  "style": {
    "styleSuffix": "统一风格后缀",
    "negativePrompt": "统一负面提示词"
  },
  "shots": [
    {
      "id": "S01",
      "act": "第一章",
      "start": 0.0,
      "end": 4.2,
      "characterId": "hero",
      "prompt": "这一镜的画面描述",
      "seed": 20261017,
      "outputPath": "assets/shots/S01.png",
      "camera": "push_in",
      "subtitle": "这一镜的字幕",
      "transition": {
        "type": "match_cut",
        "reason": "用同一个圆形物件接力到下一场"
      }
    }
  ]
}
```

规则：

- `id`、`start`、`end`、`outputPath` 必须显式写出，不能靠文件名猜。
- 有人物连续性时，用 `characterId` 指向角色锚点；不要让脚本从 prompt 里的 `slick`、`wealthy` 等关键词推断角色。
- `styleSuffix`、`negativePrompt` 和角色锚点属于资产生产契约；如果项目不使用 AI 生成，可以省略，但不要留下“看起来像有约束”的空字段。
- `transition.reason` 必须能回答“为什么现在换”。没有理由的切页不是转场。
- 画面尺寸、帧率和总时长只保留一份来源；子合成和根时间线都从 `meta` 取值，禁止一处 1920、一处 1080、另一处又写死别的数字。

## 三、接到主流程的哪一步

不要另起一套门禁，直接接主 `SKILL.md` 的七步流程：

| 主流程步骤 | 图片主导项目里的具体产物 |
|---|---|
| 1. 判片种与规格 | 确认这是图片主导的 MV / 故事片 / 讲解片，写清画幅、帧率、总时长、音频和交付形式 |
| 2. 写分镜与转场 | 写 `storyboard.json`；每镜有资产路径、起止、镜头运动、字幕和转场理由 |
| 3. 出三张定帧 | 选主体识别、关键转场、文字密集帧；先确认画法和构图，不急着批量生成 |
| 4. 做 5–8 秒样片 | 用低分辨率或少量步数做 animatic，验证时间线、Ken Burns、字幕和转场 |
| 5. 完成全片 | 批量生成或整理最终资产；每镜一个子合成；根时间线只负责编排 |
| 6. 跑自动检查 | 最终 MP4 抽帧、contact sheet、字幕可读性、layout、音频和元数据对账 |
| 7. 交付 | 最终文件、manifest、抽帧证据、已知限制和例外 |

## 四、资产生产的边界

这一节只在项目确实使用 AI 图片生成时启用。它不是 `code-motion-film` 的核心，不要把模型参数写进所有视频任务。

### 4.1 先做草稿档，再做正式档

先用低分辨率、少步数或更便宜的模型验证：

- 构图是否成立
- 主体是否可辨
- 角色是否跨镜一致
- 字幕有没有压到脸
- 镜头运动有没有越界

草稿通过后，再用正式分辨率、步数和采样参数出片。不要把最高质量档直接用在整条时间线上；单镜成本会吞掉迭代预算。

具体分辨率、步数和耗时依机器而定，必须记录本次项目的实测值，不要把它写成跨项目固定常数。

### 4.2 角色和风格要显式锚定

- 每个角色有稳定的 `characterId` 和一段可复用的外观锚点。
- 每镜 prompt = 镜头描述 + 角色锚点 + 统一风格后缀。
- 所有镜头共用一份 negative prompt，除非某一镜有明确例外并登记原因。
- 固定 seed 只用于“可复现”，不是“每镜必须一样”；同一角色可以共享 seed 策略，但不要用 seed 代替角色锚点。
- 记录模型、版本、采样器、步数、分辨率、seed、生成命令和输出路径。

### 4.3 逐镜可恢复

批量生成必须支持：

- 已存在的输出默认跳过。
- 单镜失败只记录失败，不阻塞其它镜头。
- 每镜记录耗时、输出尺寸、平均亮度或其它可比较的质量指标。
- 失败镜头可以单独重跑，不需要重做整片。
- 生成日志和最终 manifest 对得上；不能只看控制台最后一行。

## 五、工程结构

推荐把“素材、数据、子合成、根时间线、产物”分开：

```text
project/
  data/storyboard.json
  assets/shots/S01.png
  assets/shots/S02.png
  compositions/S01.html
  compositions/S02.html
  index.html
  out/final.mp4
```

结构原则：

- **一镜一个子合成**。每镜自己管理背景 plate、局部叠层、字幕、Ken Burns 和局部动画。
- **根时间线只做编排**。根文件负责总时长、子合成起止、音频、章节卡和全局层级，不把每镜细节复制进去。
- **共享常量集中管理**。画幅、fps、总时长、安全区、字体名、主色和章节时间点只定义一次。
- **子合成可单独预览**。单镜出问题时，不改根文件就能定位和重渲染。
- **资源路径相对项目根目录**。禁止一半相对路径、一半绝对路径；换机器后必须仍能构建。

## 六、静帧运动

### 6.1 Ken Burns 只算静帧运动

推近、拉远、平移静帧可以制造节奏，但它不是 3D 运镜：

- 轮廓不随视角改变。
- 看不到物体侧面、背面或内部。
- 不能证明空间关系。

如果镜头要求“环绕汽车到侧面”“从天窗进入车内”“镜头穿过门”，必须按主 skill 的逐帧相机投影处理；不要用整层 `scale` / `translate` / `rotateY` 冒充。

### 6.2 先算安全边界

任何 Ken Burns 都要检查：

- 最大缩放时，plate 是否仍覆盖整个画幅。
- 最大平移时，边缘是否露出背景或出现黑边。
- 主体是否被裁掉关键部位。
- 字幕是否始终在安全区，不跟着 plate 缩放。

实现时把缩放和位移写成具名常量，并对起始、结束和中间帧各算一次可见区域。不能只看第一帧“看起来没问题”。

### 6.3 不要把所有层一起推

背景 plate 可以有静帧运动；字幕、角标和 HUD 应固定在屏幕层。若文字跟着 plate 缩放，观众会先感到“画面在抖”，而不是“镜头在推”。

## 七、文字、字体和安全区

- 字幕使用可读性底衬：半透明渐变、局部模糊或足够对比的色块；底衬服务阅读，不要盖住主体脸部。
- 字幕固定在预留安全带；每镜根据实际空区选位置，不机械贴底。
- 字幕颜色由脚下背景决定，不由全片调色板决定。
- 每个子合成都在自己的 scoped style 内声明所需字体，不要假设根 HTML 的 `@font-face` 会自动继承。
- 验收时看最终渲染页面的 computed font，不只看源码里写了什么字体名。
- 字体 fallback 必须明确；中文项目至少确认一个可用中文字体，不要静默落到方框字。
- 字幕、章节标题和画面内标签不能互相叠字。

## 八、依赖与可复现性

- 优先本地依赖或锁定版本；不要默认依赖外部 CDN。
- 如果必须联网加载 GSAP、字体或其它资源，把它写成明确的前置条件，并在离线环境验证失败行为。
- 记录运行时版本、构建命令和输出路径。
- 同一项目不要同时维护“开发入口”和“交付入口”两套互不一致的时间线；交付前从最终入口重建。

## 九、验收：`ok: true` 不是验收完成

### 9.1 先验最终文件

从最终 MP4 或最终单文件 HTML 验收，不从开发预览、中间 PNG 或草稿视频验收。至少确认：

- 总时长与 manifest 一致。
- 分辨率、帧率、像素宽高比正确。
- 有音频时，音频流存在、时长对齐、没有明显削波。
- 镜头起止没有重叠或空档。
- 缺失素材、错误路径和 fallback 字体没有被静默放过。

### 9.2 抽帧和 contact sheet

- 全片每 1–2 秒抽一帧，拼成 contact sheet，先扫整体节奏、亮度跳变、字幕和构图。
- 动作中段、转场前后、文字出现/消失处要加密抽帧。
- 每个转场至少看交接前 5 帧、交接帧、交接后 5 帧。
- 抽帧必须来自最终文件；不能拿源图或预览页冒充。

### 9.3 layout 和运行时检查

检查器的总开关 `ok: true` 只代表它定义的规则通过，不代表视觉验收通过。

- `error`、`warning`、`info` 都要看；尤其是 `container_overflow` 这类 info 问题，可能正是边缘裁切、字幕出框或 Ken Burns 越界。
- 每条 overflow 都要判断：是真实错误，还是已经登记的有意溢出。
- 有意溢出必须用项目约定的标记显式登记，不能靠“我觉得观众看不出来”。
- 检查器报告要和抽帧结果对账；报告通过但画面有问题，以画面为准，并补规则。

## 十、常见失败模式

| 症状 | 根因 | 修法 |
|---|---|---|
| 全片像幻灯片 | 每镜只有静态图，没有时间线变化 | 加可读的局部运动、字幕节奏或真正的镜头运动；不要只加淡入 |
| 镜头像纸片翻转 | 用整层 transform 冒充环绕 | 逐帧重算投影和遮挡，或明确降级为静帧运动并说明 |
| Ken Burns 边缘露底 | 缩放/平移没有算安全边界 | 降低位移和缩放，逐帧检查最大可见区域 |
| 字幕忽大忽小 | 字幕被放进相机/plate 层 | 字幕固定在屏幕层 |
| 字幕压脸 | 只按固定底部位置放 | 按每镜空区选安全带，并检查人物位置 |
| 字体变成方框 | 根字体没有被子合成继承 | 每个子合成声明 scoped 字体，验收 computed font |
| 检查通过但画面裁切 | 忽略 info 级 overflow | 逐条看 layout findings，登记或修复 |
| 重渲染还是旧画面 | 缓存或旧 bundle | 清缓存，从最终文件抽帧，做哈希/字节对账 |
| 换机器后构建失败 | 绝对路径、外部 CDN、未锁版本 | 改为项目相对路径，锁依赖，记录前置条件 |
| 单镜失败拖垮全片 | 批量脚本没有隔离 | 已存在跳过、失败记录、单镜重跑 |

## 十一、交付清单

- [ ] `storyboard.json` 是镜头、时间、资产和转场的单一数据源。
- [ ] 角色使用显式 `characterId`，没有从 prompt 关键词猜角色。
- [ ] 草稿档已验证构图、角色、字幕和运动，再出正式档。
- [ ] 每镜有独立子合成，根时间线只负责编排。
- [ ] 画幅、fps、总时长、安全区和字体只有一份来源。
- [ ] Ken Burns 已检查最大缩放/平移边界，没有露底或裁掉主体。
- [ ] 字幕有底衬、在安全带内、没有压脸或叠字。
- [ ] 每个子合成声明 scoped 字体，最终页面 computed font 正确。
- [ ] 依赖已锁定或本地化，没有未登记的 CDN 前置条件。
- [ ] 最终 MP4 的时长、分辨率、fps、音频和镜头起止已对账。
- [ ] 已从最终文件生成 contact sheet，并覆盖转场前后与文字瞬间。
- [ ] layout 的 info 级问题已逐条处理或显式登记。
- [ ] 交付说明写清已知限制、例外和重建命令。
