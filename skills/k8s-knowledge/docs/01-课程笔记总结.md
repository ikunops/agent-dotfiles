## 一、Docker 基础

### 1. Docker 核心概念
- **Docker**：基于 Go 语言的开源容器引擎，2013 年 dotCloud 公司推出
- 思想来源于集装箱：将应用及其依赖打包到可移植的镜像中
- 容器完全使用沙箱机制，相互之间没有接口调用

### 2. Docker 优点
| 特性 | 说明 |
|------|------|
| 快 | 运行性能快，操作(启动/停止)以秒/毫秒为单位 |
| 敏捷 | 像虚拟机一样敏捷，更便宜 |
| 灵活 | 将应用和系统"容器化"，不添加额外操作系统 |
| 轻量 | 一台服务器可部署 100~1000 个容器 |
| 便宜 | 开源免费，低成本 |

### 3. Docker 核心操作
- **镜像管理**：pull、push、save、load、tag
- **容器管理**：run、start、stop、rm、exec
- **Dockerfile**：FROM、RUN、CMD、ENTRYPOINT、COPY、ADD、EXPOSE、ENV、VOLUME、WORKDIR
- **数据持久化**：Volume（`-v` 挂载）
- **网络模式**：bridge（默认）、host、joined、none
- **资源限制**：`--cpus`、`--memory`、`--memory-swap`

## 二、Kubernetes 核心资源 - Pod

### 1. Pod 是什么
- **最小调度单元**，一个 Pod 封装一个或多个容器
- Pod 内容器共享存储、网络（通过 localhost 通信）
- 共享 IP 和 Volume
- 类比：Pod = "豌豆荚"，容器 = "豆子"

### 2. Pod 类型
| 类型 | 说明 |
|------|------|
| 自主式 Pod | 直接创建，不通过控制器，故障不会自愈 |
| 控制器管理 Pod | 通过 Deployment/StatefulSet 等管理，具备自愈能力 |

### 3. Pod 生命周期
- **状态**：Pending → Running → Succeeded/Failed → Unknown
- **重启策略**：Always（默认）、OnFailure、Never
- **Init 容器**：在主容器启动前运行，完成初始化任务

### 4. 健康探测
| 探针类型 | 作用 | 探测方式 |
|----------|------|----------|
| livenessProbe | 存活检查，失败则重启容器 | httpGet/tcpSocket/exec |
| readinessProbe | 就绪检查，失败则从 Service 端点移除 | httpGet/tcpSocket/exec |
| startupProbe | 启动检查，慢启动容器防止误杀 | httpGet/tcpSocket/exec |

- 探测顺序：**startupProbe → readinessProbe → livenessProbe**
- 参数：initialDelaySeconds、periodSeconds、timeoutSeconds、failureThreshold

### 5. 临时容器 (Ephemeral Container)
- 用于**调试**正在运行的 Pod，不改动 Pod 定义
- 无端口、无探针、无资源限制、不会自动重启
- Feature Gate：`EphemeralContainers=true`
- kubectl 1.18+ 支持 `kubectl alpha debug` / `kubectl debug`

## 四、Kubernetes 控制器

### 1. ReplicaSet
- 确保 Pod 维持期望副本数（多退少补）
- 三要素：**期望副本数 + 标签选择器 + Pod 模板**
- 一般不直接使用，通过 Deployment 管理

### 2. Deployment
- 管理 ReplicaSet，提供**声明式更新**
- 支持**滚动更新**（`strategy.rollingUpdate`）
- 保留版本历史，支持**回滚**
- 适用场景：无状态应用

### 3. StatefulSet
- 管理**有状态**应用
- 提供**稳定的网络标识**（Pod 名称固定）
- **有序启停**：按 index 顺序创建/删除
- volumeClaimTemplates：每个 Pod 独立 PVC
- 适用场景：MySQL 主从、Redis 集群、ZooKeeper

### 4. DaemonSet
- 每个 Node 上运行一个 Pod
- 新节点加入自动创建，节点删除自动回收
- 适用场景：**日志收集**（fluentd）、**监控**（Node Exporter）、**存储**（glusterd/ceph）

## 五、Kubernetes 网络

### 1. Service（四层负载均衡）
| 类型 | 说明 |
|------|------|
| ClusterIP | 集群内部 IP，默认类型 |
| NodePort | 节点端口映射(30000-32767) |
| LoadBalancer | 云服务商负载均衡器 |
| ExternalName | DNS CNAME 映射 |

- **kube-proxy**：通过 iptables/ipvs 实现负载均衡
- **IPVS 模式**：Hash 表，效率高（大集群推荐）
- **IPVS 算法**：rr、wrr、lc、wlc、sh、dh

### 2. CNI 网络插件
| 插件 | 模式 | 特点 |
|------|------|------|
| Flannel | VXLAN/host-gw | 简单易用，Overlay 网络 |
| Calico | BGP | 支持 NetworkPolicy，纯三层 |
| Canal | Flannel+Calico | 兼顾简单与策略 |

### 3. Ingress Controller（七层负载均衡）
- Nginx Ingress Controller 实现 HTTP/HTTPS 路由
- 支持**高可用**（keepalive + 多副本）
- **灰度发布**策略：
  - **Header-based**：根据请求头路由
  - **Cookie-based**：根据 Cookie 分流
  - **Weight-based**：按权重切分流量（0-100%）

## 六、Kubernetes 存储

### 1. 存储卷类型
| 类型 | 说明 |
|------|------|
| emptyDir | 临时存储，Pod 删除即消失 |
| hostPath | 挂载宿主机目录 |
| NFS | 网络文件系统 |
| PV/PVC | 持久卷/持久卷声明 |
| StorageClass | 动态存储供应 |

### 2. PV/PVC 生命周期
**Provision → Bind → Use → Release → Reclaim**

- **访问模式**：ReadWriteOnce（RWO）、ReadOnlyMany（ROX）、ReadWriteMany（RWX）
- **回收策略**：Retain（保留）、Delete（删除）、Recycle（回收）

### 3. ConfigMap
- 存储**非机密**配置（key-value）
- 注入方式：**Volume 挂载**、**环境变量**
- 最大 1 MiB

### 4. Secret
- 存储**机密**数据（Base64 编码）
- 类型：Opaque、ServiceAccount、docker-registry、TLS
- 注入方式同 ConfigMap

### 5. Ceph 分布式存储
- **三种存储类型**：块存储（RBD）、文件系统（CephFS）、对象存储（RADOS Gateway）
- 核心组件：Monitor、Manager、OSD、MDS
- 通过 CSI 驱动集成到 K8s

## 七、Kubernetes 安全 - RBAC

### 1. 三层安全机制
| 层 | 说明 |
|----|------|
| 认证 (Authentication) | 验证客户端身份（Token/证书/用户密码） |
| 授权 (Authorization) | 判断是否有权访问资源 |
| 准入控制 (Admission Control) | 拦截请求，做变更/验证 |

### 2. RBAC 核心对象
- **Role**：命名空间内权限
- **ClusterRole**：集群级权限
- **RoleBinding**：绑定 Role 到 User/ServiceAccount
- **ClusterRoleBinding**：绑定 ClusterRole
- **动词**：get、list、watch、create、update、delete
