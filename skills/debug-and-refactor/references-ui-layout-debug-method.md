# UI 布局问题定位法 —— 现象驱动的必达路径（方法论 + 案例档案）

> 适用问题类：CSS/布局类视觉问题（内容出视口、留白不对称、按钮未贴合、列错位）。
> 核心洞察：**盲扫找不到，现象指认后必达** —— 用户的"一句话现象"本身就是定位入口，
> 把它映射到检查路径，比漫无目的翻样式快一个数量级。本文是方法论，「案例档案」为两次实测的完整闭环。

## 一、方法论：四招必达

### 1. 布局链路法（flex 高度链）—— 治"内容不在预期框里"
症状：内容被推出视口 / 一截看不到 / 滑块在页面而不是区域里 / 底栏按钮消失。
检查 SAME：
1. **S**cope：目标元素 → 容器 → … → 视口，把每一层祖先列出来（民例：`.db-main > .db-query-section > .db-result > .db-table-grid`）。
2. **A**lign：每层是否参与 flex 链——`display:flex; flex-direction:column`、`flex:1/min-height:0`、`overflow:hidden` 三分缺一不可。**缺 `flex:1` 或多层没 `min-height:0`，内容就会撑出容器落到外层滚动容器里。**
3. **M**ode：谁是真正的滚动宿主？已预期"网格内部滚动"却变成整页滚 → 高度链断了。
4. **E**lement：内部各子项定角色：固定段（头/工具栏/编辑条）`flex:none`，可滚段（网格/列表）`flex:1; min-height:0; overflow:auto`。
修复范式：容器 `flex:1; min-height:0; overflow:hidden` + 固定段 `flex:none` + 可滚段 `flex:1; min-height:0`。**底栏按钮（保存/取消）放可滚段之后，天然常驻。**

### 2. 几何量化法 —— 治"感觉不对但说不出哪不对"
把"感觉"变数字：`getBoundingClientRect()` 逐项量：
- 对称性：`按钮.top - 容器.top` vs `下一段.top - 按钮.bottom`，差 >2px 即不对称源。
- 贴合度：按钮高 vs 行高（容器高），富余 = 视觉"空块"。
- 重叠：两元素 left/right 区间相交即重叠。
输出一张"哪到哪几像素"的表，**不对称的那个差值继续挖**，别停在表面。

### 3. 样式考古法 —— 治"改了没生效/只生效一半"
同一选择器在历史多段定义中残留（尤其"版本号叠加"式 CSS 文件，如 `V12:…`、`V14:…` 覆盖段）：
1. `grep -n "选择器" index.css` 列出**全部**定义块。
2. 逐块比对**每个属性**，背景块里的属性可能仍在生效（本案例：老块 `.db-query-header { margin-bottom: 0.5rem }` 在 2700 行、新覆盖在 3200 行——margin 残活）。
3. 一次只覆盖一处，改完立即量测验证（别一次改三处再猜）。
判据：**新段声明了的一样生效；新段没声明的，老段值继续活着**。

### 4. 统一度量 —— 治"按钮参差/各区域有差异"
多区域按钮（工具栏/结果头/编辑条）观感不齐：统一 `height + line-height + padding:0 水平` 定高按钮，行高 = 按钮高，竖向留白只由容器 `padding` 双端等值控制（`padding: 0.25rem 0.35rem` 上下同值）。文字字号独立保持，不随按钮缩放。

## 二、症状 → 必达路径映射表（把用户一句话翻译成检查动作）

| 用户现象 | 第一检查路径 |
|---|---|
| "X 看不到 / 被截了一截 / 要滚页面才见" | 布局链路法：滚动宿主在哪？高度链哪环断了 |
| "X 和 Y 距离/上下不一致" | 几何量化：两个 gap 差多少，查 margin/padding/gap 叠加 |
| "X 变小/变窄后周围空着" | 几何量化 + 统一度量：按钮高 vs 行高富余 |
| "X 没贴上去/有空隙" | 样式考古：老块 margin-bottom/padding 残留 |
| "X 和 Y 不对齐" | 列宽/定宽：sticky 头与 body 列宽、定宽 vs 内容宽 |
| "改了没效果" | 样式考古 + 构建链路（dist 是否重建，Vite dev 是否在跑） |

## 三、案例档案 A：查询页底栏按钮被推出视口（高度链缺失）

**现象**：查询窗口执行后，"保存修改/取消"看不到；即使 9 行数据也被截一半（滑块能滑到，但按钮在屏外）。
**盲扫失败原因**：逐组件看都正常（表格内部滚动是对的），没往"外层滚动宿主"想。
**指认后定位**：量 `.db-table-grid`（内部滚动正常）→ 量 `.db-edit-controls`（bottom > 视口）→ 查祖先链发现 **`.db-query-section` 未参与 flex 高度链**（无 `flex:1; min-height:0; overflow:hidden`），内容整体挂在全局 `.db-main { overflow-y:auto }` 上 → 整页可滚、按钮滚出视口。
**修复**：`.db-query-section { display:flex; flex-direction:column; flex:1; min-height:0; overflow:hidden }` + 编辑器 `flex:none` + 网格 `flex:1; min-height:0`（去掉固定 calc 限高）+ 编辑条置于网格后常驻。
**验证**：编辑条 top 668 / bottom 692 ≤ 720，`body` 零滚动。

## 四、案例档案 B：按钮缩小后周围留白不对称

**现象**：压缩按钮衬距后，"执行/确认执行/格式化/清空"离卡片顶、底距离不一致；结果头"24 行·CSV/JSON/XLSX"按钮变小但四周空着。
**盲扫失败原因**：只改了 padding/font-size，没查"行高由谁撑"与"老样式残留"。
**指认后定位**：几何量化 `按钮到卡片顶=5px` vs `按钮底到编辑器=10px` → 差 5px → 样式考古 `grep .db-query-header` 发现**老块 `margin-bottom: 0.5rem`（2747 行）残活**（新覆盖段没声明 margin-bottom）→ 叠容器 gap 4px = 12px。
**修复**：老块 margin 清零 + 四类按钮统一 `height:1.4rem; line-height:1.4rem; padding:0 0.5rem` + 容器 `padding: 0.25rem 0.35rem`（双端等值）→ 上下留白由容器 padding 单点控制。
**验证**：顶 4px vs 底 3px（对称）；三处按钮等高 18px；结果头按钮上下 2/3px 对称。

## 五、工程纪律（从两次案例提炼）

1. **压缩类改动必须连带量化**：只改大小不留测量 = 必然留白（改完量一眼：按钮高 vs 行高）。
2. **CSS 覆盖段要"完整覆盖"**：新段声明属性时要同时覆盖老段同属性（margin/padding/gap 三兄弟最容易漏）。
3. **固定角色分工先写注释**：容器注释"固定段/可滚段"，后人改布局不破坏高度链。
4. **一行 CSS 也要验证几何**：`npm run build` 后浏览器量 gap 对称性，不比改功能轻松，但必做。
